# CMS-бэкенд CyberX Omsk

Маленький сервер, который хранит контент, редактируемый из кабинета владельца,
и принимает загрузку фото. Сайт — статический (Vite), и только «чернильная»
часть контента живёт здесь: тексты hero, клубы и фото, зоны, прайс, турнир,
акции, ссылки на бронирование.

## Локальный запуск

```bash
cd server
npm install
npm start          # http://localhost:8787
```

Проверка: `curl http://localhost:8787/health` → `{"ok":true}`

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `8787` | Порт (Render/Railway подставляют сами) |
| `CMS_KEY` | `CYBERX-OMSK-ROOT-2026` | **Секрет ключ владельца. Смените в продакшене** — им защищена запись (PUT/POST) |
| `ALLOWED_ORIGIN` | любой | Разрешённые домены-писатели через запятую, напр. `https://cyberx-omsk.ru,https://www.cyberx-omsk.ru` (GET открыт всегда — сайт должен читать контент) |

## Подключение к сайту

1. Откройте `src/config.ts` и укажите адрес:
   ```ts
   export const CMS_API_BASE = 'https://ваш-адрес-cms.example';
   ```
2. Пересоберите сайт (`npm run build`).

После этого в кабинете владельца:
- индикатор «Бэкенд подключён» становится зелёным;
- кнопка **«Опубликовать»** PUT-ит весь контент на сервер — посетители видят
  изменения сразу, без перезаливки сайта на домен;
- кнопки загрузки фото (камера ↑) отсылают файлы на сервер и подставляют URL.

Если `CMS_API_BASE` пустой — кабинет работает в локальном режиме:
кнопка «Черновик» хранит данные в localStorage браузера (удобно для разработки,
но посетителям изменения не видны).

## Деплой (10 минут)

**Render.com (бесплатно):** New → Web Service → репозиторий cyberx-omsk →
Root Directory `server` → Build `npm install` → Start `npm start`.
Добавьте переменные `CMS_KEY` и `ALLOWED_ORIGIN`.

**Railway / Fly.io:** та же команда, runtime Node.

**Свой VPS:** `npm install && npm start` под pm2:
```bash
npm i -g pm2
pm2 start index.js --name cyberx-cms
pm2 save && pm2 startup
```
Пробросьте домен через nginx/caddy (any HTTP-хост подойдёт, TLS обязателен —
сайт будет писать с https-домена).

## Данные

- `server/data.json` — опубликованный контент (создаётся при первой публикации,
  в git не попадает).
- `server/uploads/` — загруженные из кабинета фото.

Резервная копия = скопировать эти два файла. Кабинет владельца умеет
«Экспорт JSON» / «Импорт JSON» — это тоже способ бэкапа.

## Безопасность

- Чтение контента (`GET /api/content`) открыто — в нём нет секретов.
- Запись (контент, фото) только с `x-cyberx-key: <CMS_KEY>`.
- Кабинет открывается по секретному URL (`#admin?key=...`) + PIN (по умолчанию 5500,
  сменить — во вкладке «Система»).
- Не публикуйте `data.json`/`uploads` в git — они в `.gitignore`.
